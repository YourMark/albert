## Ground rules for whoever picks this up

- **Never merge a pull request.** Open it, report the CI result, stop. Mark
  merges. This is in each project's `.claude/CLAUDE.md` because it was broken
  badly on 2026-08-31.
- **Branch names are `feature/`, `fix/` or `chore/`** — and in practice these
  repos only use `feature/` and `fix/`. Not `feat/`, not `refactor/`, not
  `docs/`. Renaming a branch on GitHub **closes its PR**; it does not retarget.
- **Do not move Mark's working tree.** He runs the dev site off the checkout.
  `assets/build/` is gitignored, so the compiled JS does *not* follow a branch
  switch — you can end up serving one branch's PHP with another's JavaScript.
  If a branch switch is unavoidable, ask, then `npm run build` and put it back.
- **Keep both halves of a feature on one branch.** PHP that writes a URL and JS
  that reads it were split across two PRs; every checkout showed half the
  feature and the other half looked deleted.
- **`composer phpcs` covers `src/` only.** Lint tests explicitly:
  `./vendor/bin/phpcs --standard=phpcs.xml.dist tests/`
- **Use `npm run lint:js`,** not bare `npx eslint` — different config, and the
  bare run drowns real errors in unresolved-import noise.
- **A green CI run is not a test.** Build, lint and PHPUnit cannot detect a
  wrong `href`. There is a working browser harness — see below.

### Browser testing harness

```bash
cd ~/Sites/albert-dev
PASS=$(openssl rand -base64 24)
UID=$(herd php ~/bin/wp-cli.phar user create albert-headless-test \
  headless-test@albert-dev.test --role=administrator --user_pass="$PASS" --porcelain)
# drive with playwright (in albert-ai-butler/node_modules), log in via wp-login.php,
# ignoreHTTPSErrors: true, site is https://albert-dev.test
herd php ~/bin/wp-cli.phar user delete "$UID" --yes   # always clean up
```

Forging auth cookies does not work — this install uses custom cookie-name
constants. Log in through the form with a throwaway admin, then delete it.

WP-CLI is `herd php ~/bin/wp-cli.phar` (there is no `~/bin/wp`).

**WP-CLI caveat:** `wp eval` is neither an admin page request nor a REST
request, so `AbilitiesManager::enforce_disabled()` unregisters disabled
abilities and they vanish from any payload you build. To reproduce the
Abilities screen's context, `--require` a file that does:

```php
WP_CLI::add_wp_hook( 'muplugins_loaded', static function () {
	add_filter( 'albert/abilities/is_management_context', '__return_true', 1 );
} );
```

### Still to do

**1. `.well-known` metadata omits `none` — live OAuth interop bug.**
`src/OAuth/Endpoints/OAuthDiscovery.php:292` has
`[ 'client_secret_post', 'client_secret_basic' ]`, while
`src/OAuth/Endpoints/OAuthController.php:192` has the same list plus `'none'`.

Two independent RFC 8414 metadata builders; PR #66 fixed only the second one,
which is the non-standard `/oauth/metadata` route. `.well-known/oauth-authorization-server`
is the path RFC 8414 specifies and the one Claude Desktop via `mcp-remote`
actually fetches. So the interop failure #66's release notes claim to have
fixed is still live: loopback clients register with `none` and discovery does
not advertise it.

Fix: add `'none'` at `OAuthDiscovery.php:292`. Consider making the two builders
share one source — they have already drifted once.

**2. Coverage-gate path bug.** `tests/Integration/Abilities/ExecuteSchemaTest.php:126`
strips `$base_dir . '/WordPress/'`, so for the six `src/Abilities/WooCommerce/*`
abilities nothing is stripped and `$short` becomes an absolute machine-specific
path. Not failing today (the FQCN match on line 152 covers it), but
`$known_uncovered` is unusable for those abilities and a failure message would
print a local filesystem path. Strip `$base_dir . '/'` uniformly.

**3. Coverage gate counts skipped tests as covered.** Same file, line 152. The
six WooCommerce cases `markTestSkipped()` when WooCommerce is inactive, yet
still count as covered because the class name appears in the file. Needs
runtime coverage tracking rather than string matching — a rewrite, not a patch.

**4. PR #29 (June) is stale — decide and close.** Base `main`, CONFLICTING.
It splits uninstall into a `uninstall.php` calling two installers.
`development` now registers one unified
`register_uninstall_hook( __FILE__, [ 'Albert\Database\Installer', 'uninstall' ] )`
at `albert-ai-butler.php:105`, so the premise is gone. The one surviving idea:
a real `uninstall.php` beats `register_uninstall_hook`, which serialises a
callback into the database and can go stale. Either close it, or rework it to a
one-line `uninstall.php` calling `Albert\Database\Installer::uninstall()`.

**5. Close the review-only PRs.** #74 and #75, plus their ten `review/*`
branches. Artefacts of the 2026-08-31 unreviewed merges; no code of their own.

**6. Uncommitted in the tree:** the `NEVER merge a pull request` block added to
`.claude/CLAUDE.md`. Mark's view is that a text guardrail does not work and a
`settings.json` deny rule (`"deny": ["Bash(gh pr merge:*)"]`) is the real fix.
Decide: commit it, drop it, or replace it.

## Premium (`albert-premium-service`) — 1.2.0

Merged: #13 activity-log traceability, #14 output-schema coverage.

**1. It hooks the deprecated filter, unguarded — happening right now.**
`src/AlbertPremiumService.php:168`:

```php
add_filter( 'albert/abilities/suppliers', [ $this, 'register_supplier' ] );
```

Free 1.4.0 wraps that name in `apply_filters_deprecated()`, so **every**
abilities-registry read on a `WP_DEBUG` site emits a deprecation notice. This
is visible in WP-CLI output on the dev site today.

Apply the same fix already merged in WooCommerce (`albert-woocommerce`
`src/AlbertWooCommerceService.php`): detect
`method_exists( AbilitiesRegistry::class, 'get_sources' )` and hook
`albert/abilities/sources` when present, the old name when not. Rename
`register_supplier()` → `register_source()`. Do **not** hook the new name
unconditionally — Premium must keep working on Free 1.3.1.
`ALBERT_VERSION` cannot decide this: it reads `1.3.1` on Free's development
branch where the rename already exists.

**2. The coverage gate is self-satisfying for the one ability it was built for.**
`tests/Integration/Abilities/OutputSchemaCoverageTest.php:78` — a comment
containing the literal `ViewActivityLog`. The gate matches coverage with
`str_contains( $all_test_sources, $shortName )` and scans its own file, so
`ViewActivityLog` passes on the strength of that comment alone.

**3. `RevokeSession` and `ViewSessions` success output is never schema-checked.**
`RevokeSession`'s two integration tests both hit error paths, and
`assertSatisfiesOutputSchema()` returns early on `WP_Error`. `ViewSessions`
runs against zero sessions, so the nested `sessions[]` item schema is never
exercised. Both count as covered. Needs fixtures with at least one populated
row.

**4. Docblocks state a false cause.** `tests/TestCase.php` and the coverage
gate both say the `view-activity-log` bug escaped because "no test ran the
ability". Untrue — `MaintenanceAbilityTest` has called
`wp_get_ability( 'albert-premium/view-activity-log' )->execute( [] )` since
commit `5e1a91e`, before the bug shipped in `4ce8590`. The fixture was an
**empty log**, so the `entries[]` item schema was never reached. The real
failure mode is a narrow fixture, not a missing test — and the gate does
nothing about narrow fixtures. It was designed against a misdiagnosis.

**5. CI only tests against Free `development`.** `.github/workflows/tests.yml:177`
is `albert_free: ['development']`, with a stale comment saying it should become
`['main', 'v1.1.0']` "once Free 1.1.0 ships". Mark's decision: test against the
current **release** and `development`, i.e. `['development', 'v1.3.1']`, and
bump the pinned tag each cycle. Without this the old-Free branch of any
compatibility guard is never executed anywhere.

**6. `ViewActivityLog` is still validated by the hand-rolled
`tests/Unit/Helpers/SchemaValidator.php`,** not core's
`rest_validate_value_from_schema()`, because unit tests stub WordPress. The one
ability that actually had the bug is checked by the weaker validator. Consider
an integration test.

**7. Close review-only PR #15** and its `review/*` branches.
